Examples: SEARCH-P0241-C0888@1 searched family fol398–402 separately from place-heading images68–78; later family392/388 does not invalidate those nulls. C. Future global standard applies to every newly performed native negative search, independent of pilot person. Require actual question_id and subject association, exact query/variants/filters and actually examined units/pages/ranges. The validator can establish required structure and reference consistency, not certify that the described search was really exhaustive or correctly interpreted. coverage.completed=true means completion of the declared bounded search only. Unopened, timed-out, inaccessible or only partially examined scope cannot become a completed negative; split the actual completed subsearch and remaining access/inconclusive part explicitly.

D. Keep four concepts distinct: canonical search object@revision; canonical source_id@source_version; provider's edition/release/version; exact captured response/material snapshot. A canonical source version bump is not proof the provider changed. Stable archive ID/URL alone does not identify a frozen changing database. Unknown provider version or absent capture is permissible only as explicit, reasoned unknown. The supplied digest must name the actual captured representation (index response, metadata page, original, etc.), not imply the entire source was captured. New multi-material searches must enumerate each material/unit and its matching query/coverage; one umbrella ID/hash must not impersonate several independently searched units. Existing multi-unit legacy receipts remain unchanged.

E. A successful new apply binds the exact source revision in evidence and search_memory. Later retries of the identical accepted operation return the original receipt/hash without checking that revision against a subsequently changed current source head. Historical replay must reproduce old operations with old hashes/semantics. A new native request cannot opt out by omitting/downgrading the marker; absent marker support in low-level applyOperation is explicitly historical/library compatibility, not the supported native research write path. New revision of an old receipt must not fabricate performed_at or declare a newly performed search: preserve history, qualify inherited provenance, and distinguish actual new searches from documentary corrections. No automatic retrospective upgrade of missing metadata.

F. Person-view retrieval for new searches must use explicit search_memory.subjects and canonical question.subject_id, deduplicate by search object ID and retain one shared receipt across persons. Source/relation questions retain their genuine subject; associated persons may be explicitly included, never inferred from name fragments. Test a fresh search without legacy origins appears at every explicit subject and not an unrelated person. A question's subject must be present; additional persons require actual scope association. Mapping links without question_id stay navigation only, not a fictitious question-bound receipt.

G. Reuse is exact-scope judgement, not automatic same-hash suppression. Before repeating, inspect prior query, source edition/snapshot, bounds, limitations and later positive/OWNER facts. New keys or material versions can justify a new receipt with changed scope and explicit reason. Preserve prior negatives and changed-condition history; a negative never automatically closes a broad question or changes an identity/tree gate.
