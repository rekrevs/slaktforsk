# T-0664: Databasdump i Git

**Status**: DONE | **Size**: M
**Phase**: -

## Context

Ägaren vill 2026-09-17 använda en databasdump i Git som backupmetod och
fortsatt ignorera själva SQLite-filen. Den har aldrig spårats i den lokalt
åtkomliga Git-historiken. Befintlig full JSON-export omfattar cirka 433 MB.

## Scope

En deterministisk komprimerad export av alla tabeller via befintlig export/5,
en liten kommandoväg för save/check/restore och dokumenterad arbetsrutin.
Ingen ändring av forskningsdata, importbas, befintliga migrationsbevis,
dashboard eller historik. Commit/push av hela migrationsarbetet ingår inte.

## Acceptance Criteria

- [x] SQLite och dess sidofiler ignoreras; ingen sådan fil är spårad.
- [x] Full dump finns på fast versionshanterbar plats och kan uppdateras atomärt.
- [x] Samma data ger samma dump; kontroll upptäcker inaktuell eller skadad dump.
- [x] Dumpen återställs till en ny databas med identisk fullständig export.
- [x] Rutinen och separat mediebevarande är dokumenterade.

## Approach

Återbruka exportData/restore; håll databasen i en lästransaktion vid dumpning.
Komprimera JSON med gzip. Använd temporär fil och atomär ersättning för dumpen.
Kontrollera byteidentitet mot aktuell export och återställ verkliga data i /tmp.

## Log

Git-index och lokal historik innehåller ingen genealogy2-databas. Nuvarande
ignore-regler täcker research.sqlite och SQLite-sidofiler. Journalen består
av 39 operationer. Okomprimerad export: 433358618 byte i tabellvärden.

## Återupptagning

Uppdaterat 2026-09-17. Nästa steg: skapa wrapper, riktade tester, dump och
verkligt återställningsprov. Därefter dokumentera och avsluta uppgiften.
