# T-0032: Add life years and places to the pedigree trees and a complete person catalogue

**Status**: DONE | **Size**: M

## Context

The owner wants a version-4 checkpoint that keeps version 3's restrained,
paper-efficient design while making the family trees and person section more
informative. `PCR-2026-09-04-005` and `PCD-2026-09-04-005` define the scope.

Versions 1–3 are immutable reference editions. T-0013 has yielded back to
`READY`; its already collected archive evidence remains in the workspace and
will be resumed after this bounded edition task.

## Acceptance Criteria

- [x] Versions 1–3 remain byte-for-byte unchanged.
- [x] Both connected pedigree trees show each person's name, known life years
  and a relevant place, without depth-position codes or evidence-status prose
  inside the person nodes.
- [x] A complete catalogue contains all 62 unique people shown as nodes in the
  two trees, in tree order, with exactly one primary entry per tree position.
- [x] Every catalogue entry shows person ID, name, life years, place, branch
  and depth, plus named person-ID references to known parents, partner(s) and
  children. Non-propagating uncertain relations are not presented as known.
- [x] Every catalogue entry includes an evidence-grounded synthesis of the
  most relevant known life information and readable C-references; unknown
  information remains explicit rather than inferred.
- [x] The catalogue uses two people per portrait page and may increase the
  page count for substantive content, while retaining version 3's monochrome,
  undecorated typographic design.
- [x] A version-4 manifest, deterministic builder and structural verifier make
  the edition reproducible and check the catalogue/tree invariants.
- [x] Every rendered page is visually inspected; no text, connector, footer or
  catalogue field clips or overlaps.

## Approach

Reuse version 3's frozen narrative, maps, stories, source close readings and
references. Replace only the tree metadata and portrait-page sequence. Freeze
the 30 nearer-generation tree positions and their display metadata in the
version-4 manifest; reuse the 32 depth-5 position records from the version-2
content manifest. Build relationships from the current canonical project data
with the same non-propagation statuses as the ancestry model.
